## 3. Functional Requirements

### Authentication - Login
- **[FR-001]** (Must Have) The system shall allow users to authenticate using email/password credentials

### Authentication - OTP
- **[FR-002]** (Must Have) The system shall send and verify one-time passwords via SMS for mobile login

### Authentication - MFA
- **[FR-003]** (Should Have) The system shall support multi-factor authentication for enhanced security

### User Management - Profiles
- **[FR-004]** (Must Have) The system shall maintain user profiles with essential information

### User Management - Roles
- **[FR-005]** (Must Have) The system shall support role-based access control with configurable permissions

### User Management - Branch Access
- **[FR-006]** (Must Have) The system shall support branch-specific user access controls

### Billing - Order Creation
- **[FR-007]** (Must Have) The system shall allow creation of sales orders with products/services

### Billing - Invoice Generation
- **[FR-008]** (Must Have) The system shall generate invoices automatically upon order completion

### Billing - GST Invoice
- **[FR-009]** (Must Have) The system shall generate GST-compliant invoices with proper tax calculations

### Billing - GST Slabs
- **[FR-010]** (Must Have) The system shall support multiple GST slabs (5%, 12%, 18%, 28%)

### Billing - HSN Codes
- **[FR-011]** (Should Have) The system shall support HSN code mapping for products

### Billing - E-Invoice
- **[FR-012]** (Should Have) The system shall generate e-invoices via GST e-invoice portal

### Billing - E-Way Bill
- **[FR-013]** (Should Have) The system shall generate e-way bills for applicable transactions

### Billing - Card Payment
- **[FR-014]** (Should Have) The system shall accept card payments via integrated POS

### Billing - Split Payment
- **[FR-015]** (Should Have) The system shall support multiple payment methods in a single transaction

### Billing - Partial Payment
- **[FR-016]** (Should Have) The system shall allow partial payments with remaining balance tracking

### Billing - Returns
- **[FR-017]** (Should Have) The system shall process product returns and generate credit notes

### Inventory - Product Catalog
- **[FR-018]** (Must Have) The system shall maintain a product catalog with name, price, and description

### Inventory - Barcode
- **[FR-019]** (Should Have) The system shall support barcode scanning for product lookup

### Inventory - Stock Tracking
- **[FR-020]** (Must Have) The system shall track real-time stock quantities

### Inventory - Low Stock Alert
- **[FR-021]** (Must Have) The system shall alert users when stock falls below threshold

### Inventory - Multi-Location
- **[FR-022]** (Should Have) The system shall track inventory across multiple locations/branches

### Inventory - Batch Tracking
- **[FR-023]** (Should Have) The system shall track batch numbers and expiry dates

### Pricing - Price Management
- **[FR-024]** (Must Have) The system shall manage product prices with support for retail pricing

### Pricing - Wholesale Pricing
- **[FR-025]** (Should Have) The system shall support wholesale pricing with volume discounts

### Pricing - Tiered Pricing
- **[FR-026]** (Should Have) The system shall support tiered pricing based on quantity

### Pricing - Discounts
- **[FR-027]** (Must Have) The system shall apply percentage and fixed amount discounts

### Pricing - Loyalty Points
- **[FR-028]** (Should Have) The system shall award loyalty points on purchases

### Pricing - Points Redemption
- **[FR-029]** (Should Have) The system shall allow customers to redeem loyalty points

### Service - Service Booking
- **[FR-030]** (Must Have) The system shall allow booking of services with date/time slots

### Service - Job Card
- **[FR-031]** (Should Have) The system shall create and manage job cards for service orders

### Service - Warranty
- **[FR-032]** (Should Have) The system shall track warranty periods and validate claims

### Notifications - SMS
- **[FR-033]** (Should Have) The system shall send SMS notifications for critical updates

### Reporting - Inventory Reports
- **[FR-034]** (Should Have) The system shall generate inventory status and movement reports

### Reporting - Dashboard
- **[FR-035]** (Should Have) The system shall display a real-time dashboard with key metrics

### Integrations - Payment Gateway
- **[FR-036]** (Should Have) The system shall integrate with payment gateway for online transactions

### Integrations - Accounting Sync
- **[FR-037]** (Could Have) The system shall sync data with accounting software

### Integrations - E-commerce Sync
- **[FR-038]** (Could Have) The system shall sync inventory and orders with e-commerce platforms

## 4. User Flows

### 4.001 Retail Sale Flow
Standard retail sale transaction from product selection to invoice

1. **Login to POS** (Cashier)
   - System: Authenticate user
   - Result: User authenticated
2. **Search/Scan Product** (Cashier)
   - System: Search product catalog
   - Result: Product added to cart
3. **Apply Discounts** (Cashier)
   - System: Calculate discounts
   - Result: Discounts applied
4. **Select Payment Method** (Customer)
   - System: Display payment options
   - Result: Payment method selected
5. **Process Payment** (Customer)
   - System: Process via payment gateway
   - Result: Payment confirmed
6. **Generate Invoice** (System)
   - System: Create invoice record
   - Result: Invoice generated with GST
7. **Update Inventory** (System)
   - System: Decrement stock
   - Result: Stock updated
8. **Print/Send Invoice** (System)
   - System: Generate invoice
   - Result: Invoice delivered

### 4.002 Customer Registration Flow
New customer signup and profile creation

1. **Initiate Signup** (Customer)
   - System: Display registration form
   - Result: Form shown
2. **Enter Details** (Customer)
   - System: Validate input
   - Result: Data validated
3. **Verify OTP** (Customer)
   - System: Send and verify OTP
   - Result: Phone verified
4. **Set Password** (Customer)
   - System: Hash and store password
   - Result: Account created
5. **Profile Setup** (Customer)
   - System: Save profile data
   - Result: Profile complete
6. **Assign Loyalty** (System)
   - System: Create loyalty record
   - Result: Loyalty enabled

### 4.003 Purchase Order Flow
Wholesale purchase order creation and fulfillment

1. **Login to System** (Sales Rep)
   - System: Authenticate user
   - Result: User authenticated
2. **Search Customer** (Sales Rep)
   - System: Search customer database
   - Result: Customer selected
3. **Add Products** (Sales Rep)
   - System: Add to order
   - Result: Products added
4. **Apply Wholesale Pricing** (System)
   - System: Calculate wholesale rates
   - Result: Prices updated
5. **Apply Volume Discounts** (System)
   - System: Calculate tiered pricing
   - Result: Discounts applied
6. **Generate Proforma Invoice** (System)
   - System: Create proforma
   - Result: PI generated
7. **Confirm Order** (Customer)
   - System: Update order status
   - Result: Order confirmed
8. **Generate Tax Invoice** (System)
   - System: Create invoice with GST
   - Result: Tax invoice generated
9. **Update Inventory** (System)
   - System: Decrement stock
   - Result: Stock updated

### 4.004 Service Booking Flow
Service appointment booking and completion

1. **Select Service** (Customer)
   - System: Display available services
   - Result: Service selected
2. **Choose Date/Time** (Customer)
   - System: Show available slots
   - Result: Slot selected
3. **Provide Details** (Customer)
   - System: Capture service info
   - Result: Details captured
4. **Confirm Booking** (Customer)
   - System: Create appointment
   - Result: Booking confirmed
5. **Send Confirmation** (System)
   - System: Send notification
   - Result: Customer notified
6. **Service Completion** (Technician)
   - System: Update job card
   - Result: Service done
7. **Generate Invoice** (System)
   - System: Create invoice
   - Result: Invoice generated
8. **Collect Payment** (Customer)
   - System: Process payment
   - Result: Payment received

## 7. Security Considerations

- JWT-based authentication with refresh token rotation
- Password hashing using bcrypt with salt rounds
- HTTPS/TLS encryption for all communications
- Role-based access control (RBAC)
- Input validation and SQL injection prevention
- Rate limiting on API endpoints
- Audit logging for sensitive operations
- Data encryption at rest for sensitive information
- CORS configuration for API security

## 12. Risks & Mitigations

| Risk | Mitigation |
|------|-----------|
| Payment gateway integration failures | Implement retry logic and fallback to alternate payment methods |
| Data sync issues in offline mode | Implement conflict resolution strategy and audit logs |
| High transaction volume impacting performance | Implement horizontal scaling and database optimization |
| GST compliance errors | Regular audit of tax calculations and third-party verification |
